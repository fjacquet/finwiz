# Change Request: CR-2025-08-09-02 — Pydantic Contracts for Inter‑Agent Data & Reporter Inputs

Date: 2025-08-09 09:12 CEST
Author: Cascade (Senior Trusted Financial Advisor)
Status: Proposed
Scope: Introduce strict Pydantic v2 data contracts for inter-agent communication and final reporter inputs; validate at boundaries; publish JSON Schemas; add contract tests; ensure backwards-compatible rollout.

[TOC]

## Objectives

- Secure inter-agent outputs with strict schemas to prevent drift and malformed payloads.
- Gate the final tool‑less reporter behind a single validated aggregate input (`ReporterInput`).
- Improve reliability, testability, and documentation via JSON Schema artifacts and contract tests.

---

# Recommended Actions

- **[Schema package]** Create `src/finwiz/schemas/`
  - `schemas/common.py`: shared enums/types (`RiskAssessmentStandardized`, risk levels, helpers)
  - `schemas/stock.py`: `TenKInsight`, `SentimentItem`, `MarketSentiment`
  - `schemas/etf.py`: `ETFFactsheet`, `ETFTopHolding`, `ETFRisk` (alias to standardized risk)
  - `schemas/crypto.py`: `CryptoThesis`, `CryptoRisk` (alias to standardized risk)
  - `schemas/report.py`: `ReporterInput` (aggregate, extra=forbid)

- **[Model policies]** Pydantic v2 strictness
  - Set `model_config = { 'extra': 'forbid', 'str_strip_whitespace': true }` on all models.
  - Use precise types: `HttpUrl`, `AwareDatetime`, bounded floats, Literals for sections/labels.
  - Add `schema_version: int = 1` on top‑level models for forwards evolution.

- **[Producer validation]** Validate at task boundaries
  - Producers (tasks/tools) construct models and `model_dump()` for persistence.
  - Orchestrator validates incoming JSON (`Model.model_validate(data)`) before passing downstream.
  - On validation error: log with context (crew, task, ticker), mark item invalid, continue run.

- **[Reporter gate]** Tool‑less final reporter consumes only validated input
  - Reporter entrypoint requires `ReporterInput` instance; reject raw dicts and extra keys.
  - This preserves the rule from `docs/DESIGN_PRINCIPLES.md` and `docs/output_formatting_guide.md` while improving safety.

- **[JSON Schema docs]** Publish schemas for transparency
  - Export via `Model.model_json_schema()` into `docs/schemas/*.json`.
  - Optional: add `docs/schemas/README.md` describing each contract and example payloads.

- **[Tests]** Add contract & conformance tests
  - `tests/test_contract_stock.py`: validate sample `TenKInsight`, `MarketSentiment`.
  - `tests/test_contract_reporter.py`: assert `ReporterInput(extra='forbid')` and minimal valid payload renders HTML sections.
  - `tests/test_contract_risk.py`: enforce standardized 0–5 risk scale mapping and label consistency.

- **[Backwards compatibility]** Gradual rollout
  - Config flag `VALIDATION_STRICTNESS` with modes: `off | warn | error` (default `warn`).
  - Telemetry/logging around validation failures to guide prompt/schema tuning.

- **[Developer ergonomics]** Examples & fixtures
  - Provide typed examples in `docs/schemas/examples/` and test fixtures under `tests/fixtures/`.
  - Pre-commit hook (optional): quick schema check on fixture updates.

# Proposed Changes (By Artefact)

- **[Code]** `src/finwiz/schemas/` (new)
  - Implement models listed above with strict configs and docstrings.

- **[Orchestrator]** (where tasks pass outputs)
  - Insert validation steps on load/merge; convert failures to structured warnings/errors based on `VALIDATION_STRICTNESS`.

- **[Reporter]**
  - Update reporter entry to accept `ReporterInput` only; remove acceptance of untyped dicts.

- **[Docs]** `docs/schemas/` (new)
  - Export JSON Schemas; write short README with contract overview and versioning policy.

- **[Tests]** `tests/`
  - Add contract tests and reporter conformance tests as above.

---

# Acceptance Criteria

- **[Strictness]** All producers validate outputs; `extra` keys are rejected (forbid) during reporter ingestion.
- **[Aggregate Input]** Reporter accepts only `ReporterInput` and renders required HTML sections without schema errors.
- **[Risk Normalization]** A single 0–5 scale (or mapped labels) enforced across Stock/ETF/Crypto.
- **[Schema Docs]** JSON Schemas published under `docs/schemas/` with examples.
- **[Tests Pass]** `uv run pytest` passes; contract tests included by default; integration still optional.

---

# Risks & Mitigations

- **Schema drift causing failures** → Start with `warn` mode; add fixtures and logs; escalate to `error` once stable.
- **Prompt friction** → Provide examples close to model shapes; add helpful error messages.
- **Performance concerns** → Validate once per boundary; models are lightweight; negligible overhead.
