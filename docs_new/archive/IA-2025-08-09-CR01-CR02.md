# Impact Analysis — CR-2025-08-09-01 and CR-2025-08-09-02

Date: 2025-08-09 09:13 CEST
Author: Cascade (Senior Trusted Financial Advisor)
Status: Proposed

[TOC]

## Summary

- CR-2025-08-09-01: Standardize cross-crew contracts (10‑K insights, market sentiment, risk normalization), enforce tool‑less reporter, add tests, caching, and config hygiene.
- CR-2025-08-09-02: Introduce strict Pydantic v2 models for inter‑agent data and a single `ReporterInput` aggregate; boundary validation; JSON Schema docs; contract tests; gradual rollout.

## Objectives Alignment

- Improve output quality, reproducibility, and investor suitability (1,000 CHF DCA context).
- Prevent schema drift and malformed payloads via typed contracts and validation.
- Preserve the rule: final reporter has no tools; it only consumes validated upstream context.

---

# Components Impacted

- **YAML Tasks & Agents**
  - Stock: add explicit keys for `ten_k_insights`, `market_sentiment`, standardized risk.
  - ETF: add `factsheet_highlights`, `top_holdings`, standardized risk.
  - Crypto: add `thesis_bullets`, standardized risk.
  - Reporter tasks: require "Synthèse 10‑K" and "Sentiment du Marché" sections fed from standardized keys.

- **Orchestrator**
  - Validate producer outputs at boundaries; aggregate into `ReporterInput`.
  - Add short‑lived cache for repeated news/search queries.

- **Reporter (tool‑less)**
  - Accept only `ReporterInput` (validated) and render HTML per `docs/output_formatting_guide.md`.

- **Testing**
  - Contract tests for schemas and sample payloads.
  - Reporter output conformance tests (HTML sections, emojis, no tools on final agent).

- **Docs**
  - JSON Schemas under `docs/schemas/` + examples; link from change requests.

---

# Risks

- **Schema drift breaking runs**
  - Mitigation: `VALIDATION_STRICTNESS=warn` initially; fixtures; contract tests.
- **Latency/cost from added extractions**
  - Mitigation: caching + async execution for I/O tasks.
- **Upstream/Downstream mismatch**
  - Mitigation: publish schemas and examples; enforce `extra='forbid'` at reporter gate.

---

# Effort (Consolidated)

- Schemas + validation wiring + docs: ~1.5–2 days
- YAML and prompt updates + caching: ~1–1.5 days
- Tests (contracts + reporter conformance + SEC extension): ~1–1.5 days
Total: ~3–4 days

---

# Backwards Compatibility & Rollout

- Start with `VALIDATION_STRICTNESS=warn` to surface issues without failing runs.
- Feature flags: `enable_sec_10q_8k`, `enable_etf_factsheet_extraction`.
- Reporter continues to be tool‑less; only boundary validation is added.

---

# Acceptance Criteria (Combined)

- Reporter HTML passes `docs/output_formatting_guide.md`, includes required sections.
- Final reporter agent has zero tools (enforced/tested).
- All crews output standardized keys; reporter consumes `ReporterInput` without extra keys.
- JSON Schemas published; contract and conformance tests pass.

---

# Implementation Plan (Initial Steps)

1) Create schema package `src/finwiz/schemas/` with `common.py`, `stock.py`, `report.py`, and `__init__.py`.
2) Add docs placeholder `docs/schemas/README.md`.
3) Wire basic validation at orchestrator boundaries (follow‑up PR).
4) Update reporter entrypoint to accept `ReporterInput` (follow‑up PR).
5) Add contract and reporter tests (follow‑up PR).

---

# Decision

Proceed with implementation starting with schema package and docs scaffolding now; subsequent PRs will wire validation, update YAML contracts, and add tests.
