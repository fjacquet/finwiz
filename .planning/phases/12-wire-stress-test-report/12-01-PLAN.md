# Plan 12-01: Wire Stress Test Results into HTML Report

## Goal

Close RISK-04 gap: stress test results (already calculated and stored in `state.stress_test_results`) appear in the production HTML report.

## must_haves

1. `PythonReportGenerator` generates a stress test section in the HTML output
2. `ReportingOrchestrator._generate_python_report()` passes stress test data from state to the generator
3. HTML contains scenario name, total portfolio impact, and per-holding impact table with sensitivity labels
4. Generator gracefully handles empty/missing stress test data (no error, no empty section)
5. All existing tests still pass, new test verifies rendering

## Context

**Production report flow (verified):**
```
ReportingOrchestrator.report()
  → _generate_python_report(portfolio_review, deep_analysis_results)
    → generate_python_report() convenience function
      → PythonReportGenerator.generate_family_financial_plan()
        → _generate_html_report() — builds inline HTML via f-strings
```

`PythonReportGenerator._generate_html_report()` builds the full HTML inline (NOT using Jinja2 templates). Existing sections use `self._generate_X_section()` methods called from `_generate_html_report()`.

`FinalReportGenerator` with Jinja2 templates is NOT in the production flow — it exists but is unused.

`state.stress_test_results` is `list[dict]` (each dict is `PortfolioStressTestResult.model_dump()`). Each result contains:
- `scenario.name`, `scenario.description`, `scenario.scenario_type`
- `total_portfolio_impact_pct`, `total_projected_pnl`
- `holding_impacts[]` with: `ticker`, `sector`, `beta`, `projected_change_pct`, `sensitivity_label`
- `most_affected[]`, `least_affected[]`
