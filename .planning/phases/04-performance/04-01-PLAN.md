  <action>
1. Install aiolimiter: `uv add aiolimiter`

2. Refactor `RateLimiter.__init__()`:
   - Import `from aiolimiter import AsyncLimiter`
   - Create a `self._limiters: dict[APIProvider, AsyncLimiter]` mapping
   - For each provider in `self.config`, create an `AsyncLimiter(max_rate, time_period)` where:
     - `max_rate = config.burst_limit` (burst capacity)
     - `time_period = 60.0 / config.requests_per_minute * config.burst_limit` (refill window that achieves the correct per-minute rate)
   - KEEP `self.request_history`, `self.last_request_time`, `self.retry_counts` for stats/monitoring
   - REMOVE `self._lock` (asyncio.Lock) -- aiolimiter handles synchronization internally

3. Refactor `RateLimiter.acquire()`:
   - Remove the `async with self._lock:` block
   - Replace sliding window check + cooldown sleep with:
     ```python
     limiter = self._limiters.get(provider)
     if limiter:
         await limiter.acquire()  # Non-blocking wait for token
     ```
   - KEEP the request history recording for stats (append RequestRecord after acquire)
   - KEEP the rate limit exceeded logging (but it should now be rare since aiolimiter handles queuing)

4. Refactor `RateLimiter.wait_for_availability()`:
   - Simplify to just call `self.acquire()` since aiolimiter handles waiting internally
   - Keep the max_wait_time safety with `asyncio.wait_for()`:
     ```python
     async def wait_for_availability(self, provider, endpoint=""):
         try:
             await asyncio.wait_for(self.acquire(provider, endpoint), timeout=300)
         except TimeoutError:
             raise TimeoutError(f"Rate limit timeout for {provider}")
     ```

5. KEEP these methods unchanged:
   - `get_retry_delay()` -- retry logic, not rate limiting
   - `should_retry()` -- retry logic
   - `record_failure()` -- monitoring
   - `get_stats()` -- monitoring
   - `_clean_old_requests()` -- still useful for stats
   - `_get_current_stats()` -- still useful for stats
   - `_check_rate_limits()` -- can keep for monitoring/logging

6. KEEP `with_rate_limit()` function unchanged -- it already calls `wait_for_availability()` which will use the new token bucket internally

7. KEEP `get_rate_limiter()` function unchanged -- it returns RateLimiter instance with same config

8. KEEP `DEFAULT_RATE_LIMITS` and `RateLimitConfig` unchanged -- they're used to configure the AsyncLimiter instances

Important: The file is 431 lines. After refactoring, ensure it stays under 300 lines by removing dead code (the sliding window check methods can be simplified since aiolimiter handles rate enforcement). If over 300 lines, the stats/monitoring methods can remain since they're still used for observability.
