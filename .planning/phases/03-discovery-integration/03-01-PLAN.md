  <name>Task 1: Create NewcomerDiscoveryPipeline with portfolio exclusion and output persistence</name>
  <files>src/finwiz/scoring/discovery/pipeline.py</files>
  <action>
Create `NewcomerDiscoveryPipeline` class in `src/finwiz/scoring/discovery/pipeline.py` that orchestrates the full discovery workflow for a single asset class. The class should:

1. **Constructor** `__init__(self, asset_class: str)`:
   - Accept `asset_class` ("stock", "etf", or "crypto")
   - Initialize `self.portfolio_tickers: set[str]` by calling `_load_portfolio_tickers()`
   - Store `asset_class` as instance variable
   - Define module-level constants: `ENRICHMENT_SCORE_THRESHOLD = 0.80` and `MAX_ENRICHMENT_CANDIDATES = 10`

2. **Portfolio loading** `_load_portfolio_tickers(self) -> None`:
   - Read all three CSV files (`data/stock.csv`, `data/etf.csv`, `data/crypto.csv`) using `csv.DictReader`
   - For each row, get the `"Ticker"` column, strip whitespace
   - Normalize: strip `Yahoo:` prefix (case-insensitive check via `.upper().startswith("YAHOO:")` then `.split(":", 1)[1]`)
   - For crypto tickers, also strip `-USD` suffix for comparison
   - Store all tickers as uppercase in `self.portfolio_tickers` set
   - Wrap in try/except: if a CSV doesn't exist or is malformed, log warning and continue (don't crash)

3. **Main pipeline** `discover(self, session_id: str) -> NewcomerDiscoveryResult`:
   - Step 1: Call `_gather_candidates()` to get raw candidates from all screeners
   - Step 2: Filter out portfolio holdings: `[c for c in candidates if c.ticker.upper() not in self.portfolio_tickers]`
   - Step 3: Call `_score_candidates(candidates)` to score all remaining candidates
   - Step 4: Sort by `composite_score` descending
   - Step 5: Call `_persist_result(result, self.asset_class)` to save JSON
   - Step 6: Return `NewcomerDiscoveryResult` with candidates, asset_class, session_id, timestamp, and summary metadata

4. **Candidate gathering** `_gather_candidates(self) -> list[NewcomerCandidate]`:
   - Instantiate `DynamicUniverseProvider` from `scoring.discovery.universe_provider`
   - Instantiate `IPOScreener` from `scoring.discovery.ipo_screener`
   - Instantiate `BreakoutDetector` from `scoring.discovery.breakout_detector`
   - Instantiate `MomentumScanner` from `scoring.discovery.momentum_scanner`
   - Call each one's discovery method, collect candidates
   - Wrap each call in try/except: if one screener fails, log warning, continue with others
   - Deduplicate candidates by ticker (keep first occurrence)
   - Return combined list

5. **Scoring** `_score_candidates(self, candidates: list[NewcomerCandidate]) -> list[NewcomerCandidate]`:
   - Instantiate `CandidateScorer` from `scoring.discovery.candidate_scorer`
   - Score each candidate via the scorer
   - Return candidates with updated `composite_score` and `grade` fields

6. **Output persistence** `_persist_result(self, result: NewcomerDiscoveryResult, asset_class: str) -> None`:
   - Create `output/discovery/` directory with `Path("output") / "discovery"` and `.mkdir(parents=True, exist_ok=True)`
   - Write to `output/discovery/newcomer_{asset_class}.json`
   - Use `json.dump(result.model_dump(), f, indent=2, default=str)` -- the `default=str` is MANDATORY per project rules
   - Wrap in try/except: log warning on failure, don't crash

7. **Legacy format conversion** `_to_legacy_format(self, result: NewcomerDiscoveryResult, start_time: float) -> dict[str, Any]`:
   - Convert `NewcomerDiscoveryResult` to the dict format expected by `DiscoveryOrchestrator`: `{"opportunities": [...], "analysis_summary": "...", "performance_metrics": {...}}`
   - Each candidate becomes a dict with keys: `ticker`, `name`, `grade`, `composite_score`, `recommendation`, `rationale`
   - `performance_metrics` includes: `execution_time_seconds`, `opportunities_found`, `cost_usd: 0.0`, `llm_calls_made: 0`, `method: "newcomer_discovery_pipeline"`

Use `from finwiz.tools.logger import get_logger` for logging. Import Phase 2 modules lazily inside methods (not at module top level) to avoid import errors if Phase 2 structure differs slightly. All exception handlers must use specific exception types where possible (ValueError, FileNotFoundError, OSError) with `Exception` only as the outermost fallback.
