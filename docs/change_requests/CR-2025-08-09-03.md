# Change Request: Strict Ticker Correctness Validation (Equities/ETFs/Crypto)

- ID: CR-2025-08-09-03
- Date: 2025-08-09
- Owner: FinWiz Engineering
- Status: Proposed

## Background / Problem Statement

Recent reports (e.g., `output/finwiz_family_financial_plan.html`) contained several incorrect/ambiguous tickers (e.g., `CSH+`, delisted/ambiguous `CLNT`, unclear `BATM`, etc.). The root issue is the absence of a strict correctness validation layer before these symbols reach the final tool-less reporter.

Swiss availability is not the immediate concern. The priority is to ensure symbols actually exist and are unambiguous on authoritative sources.

## Goals

- Enforce strict ticker existence/correctness validation upstream of the reporter.
- Validate equities/ETFs using Yahoo Finance; validate crypto using Coinbase Products API.
- Auto-correct or discard invalid/ambiguous symbols before they propagate.
- Maintain the final reporter as tool-less and contract-driven.

## Non-Goals

- Country/regional availability checks (e.g., UCITS/Swiss). Explicitly out of scope.
- Portfolio/broker selection logic.

## Scope of Work

1. New reusable tool: TickerExistenceValidationTool
   - Location: `src/finwiz/tools/ticker_validation_tool.py`
   - Validates symbol existence:
     - Equities/ETFs via `yfinance.Ticker(symbol).info` and `quoteType` checks
     - Crypto via Coinbase Products API (`https://api.exchange.coinbase.com/products`)
   - Output payload:

     ```json
     {
       "symbol": "AAPL",
       "asset_class": "stock|etf|crypto|auto",
       "valid": true,
       "reason": null,
       "meta": {"exchange": "NASDAQ", "quoteType": "EQUITY", "source": "yahoo"}
     }
     ```

   - No Switzerland/UCITS logic.

2. Integrate into specialized crews (tools only; reporter remains tool-less)
   - `src/finwiz/crews/stock_crew/stock_crew.py`: add tool to `tools`
   - `src/finwiz/crews/etf_crew/etf_crew.py`: add tool to `tools`
   - `src/finwiz/crews/crypto_crew/crypto_crew.py`: add tool to `research_tools` for analyst tasks

3. Tighten YAML task prompts to require validation and JSON appendix

   - `src/finwiz/crews/stock_crew/config/tasks.yaml`:
     - Require calling the validator for each proposed ticker
     - Auto-correct/replace invalid ones; otherwise discard
     - Append a machine-readable JSON appendix `validated_tickers[]`
   - `src/finwiz/crews/etf_crew/config/tasks.yaml`:
     - Same for ETFs; appendix `validated_etfs[]`
   - `src/finwiz/crews/crypto_crew/config/tasks.yaml`:
     - Validate against Coinbase; appendix `validated_symbols[]`

4. Optional but recommended schema addition (leveraging CR-2025-08-09-02)

   - New Pydantic schema `ValidatedTicker` (v2) in `src/finwiz/schemas/validation.py`:

     ```python
     class ValidatedTicker(BaseModel):
         symbol: constr(min_length=1, max_length=15)
         asset_class: Literal["stock", "etf", "crypto"]
         valid: bool
         reason: str | None = None
         meta: dict[str, Any] = Field(default_factory=dict)
     ```

   - Export JSON Schema docs under `docs/schemas/ValidatedTicker.schema.json` and example.
   - Use `VALIDATION_STRICTNESS` (warn/error) from CR-2025-08-09-02 for boundary checks in tests.

## Technical Design

- Yahoo path: treat empty `info` as invalid; require `quoteType` ∈ {`EQUITY`,`COMMONSTOCK`,`PREFERREDSTOCK`} for stocks or `ETF` for ETFs.
- Crypto path: symbol is valid if any Coinbase product pair starts with `SYMBOL-`.
- Asset class handling: accept `auto`; infer from Yahoo `quoteType` for non-crypto.
- Tool returns a compact, serializable dict suitable for LLM consumption and schema validation.

## Configuration

- New env (optional): `TICKER_VALIDATION_STRICTNESS=warn|error` (default: `warn`). When `error`, agents must discard/replace invalid symbols; when `warn`, they may attempt one correction pass and then drop.

## Testing & Validation

- Unit tests for the tool (mock Yahoo/HTTP):
  - Valid stock (`AAPL`), valid ETF (e.g., `VWRA.L` if present), invalid symbol (`CSH+`).
  - Valid crypto (`BTC` present on Coinbase), invalid crypto (`NEUR` not on Coinbase).
- Contract tests for task outputs (appendix presence and structure) using `VALIDATION_STRICTNESS=warn`.
- E2E dry run to ensure the final reporter only receives validated symbols.

## Risks & Mitigations

- Yahoo `info` instability: cache minimal fields, guard exceptions, keep output small.
- Coinbase API availability: short timeout and graceful failure with `valid=false` + reason.
- LLM prompt adherence: explicit numbered steps + JSON appendix examples in YAML.

## Rollout Plan

1. Land tool + schema (optional) behind prompts.
2. Update Stock/ETF/Crypto tasks.
3. Run CI tests; fix regressions.
4. Perform one local generation; verify no invalid tickers leak into reporter input.

## Acceptance Criteria

- Every stock/ETF/crypto symbol included in intermediate outputs has a corresponding validated entry.
- Invalid or ambiguous symbols are absent from the final HTML or replaced with validated ones.
- Reporter agent remains tool-less.

## Out of Scope / Future Work

- Country/UCITS availability checks (can be a separate CR if needed later).
